# History (Riwayat Baca & Tonton) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Riwayat baca komik (per chapter + read-set abu-abu di ChapterList) dan riwayat tonton anime (per episode), drakor/movie (episode + posisi menit), tersimpan server-side di Neon Postgres, dengan halaman/tab Riwayat terikat akun Clerk dan teks resume.

**Architecture:** Satu tabel `history` dengan PK `(user_id, domain, ref)` + `payload JSONB`; tulis via Server Actions (upsert idempotenn, fire-and-forget dari client); baca server-side di `/history` dan halaman watch (sudah dynamic), read-state komik dari client via Server Action agar detail manga tetap ISR. Tanpa ORM — driver `@neondatabase/serverless` + SQL mentah. Helper murni di `lib/history-state.ts` agar teruji tanpa DB/Clerk.

**Tech Stack:** Next.js 15 App Router, React 19, Tailwind 4 (token DESIGN.md), Clerk 7, Neon Postgres (`@neondatabase/serverless`), Vitest.

**Spec:** `docs/superpowers/specs/2026-10-26-history-design.md` (pada awal eksekusi: salin dari `C:\Users\Fahril\.opencode\plan\2026-10-26-history-design.md` ke path repo tersebut; plan file ini juga disalin ke `docs/superpowers/plans/2026-10-26-history.md`).

- Semua env baru: **hanya `DATABASE_URL=postgresql://...`** (`DATABASE_URL` ditampung di `.env.local`, tulis placeholder di `.env.example` — JANGAN menyentuh `.env`).
- Tanpa ORM, tanpa Cheerio, tanpa library baru selain `@neondatabase/serverless`.
- Recording selalu `void action(...).catch(() => {})` — UI tidak pernah menunggu; kegagalan history diam-diam.
- Pesan error Bahasa Indonesia selaras pola `lib/*` existing ("...belum dikonfigurasi").
- Warna/tone: read marker memakai `--text-muted`; chip/tombol resume memakai `--accent` (amber) dengan teks `--accent-ink`; ikon SVG garis berat 1.75 lewat `Icon.tsx`.
- Git: repo tampak semi-inisiasi (`.git\` ada) — mulai dengan `git status`; bila belum repo valid, `git init` terlebih dahulu.
- Semua commit kecil per task, message konvensional (`feat:`/`test:`/`chore:`).

## Review Focus
1. **Buka ulang / double-tab** → harus idempotenn (tidak menambah baris baru, posisi menit tidak tergandakan). Pin: integration test upsert-roundtrip di Task 3.
2. **Rewind posisi menit** (posisi baru < tersimpan) → tersimpan selalu maksimum. Pin: `mergeWatchPayload` test di Task 2.
3. **Episode mismatch** (payload milik episode lain dari yang dibuka) → resume chip TIDAK muncul / seek TIDAK terjadi. Pin: `resumeFor` test di Task 2, dikonsumsi Task 6.
4. **Episode selesai** (position/duration ≥ 0,95) → chip resume disembunyikan (arahkan alamial: tidak ada auto-resume karena nuance jadi). Pin: `isCompleted`+`resumeFor` test di Task 2.
5. **Nomor chapter float** ("10.5" ≠ 10) → read marker exact per nomor. Pin: `inRanges`/`mergeRanges` test float di Task 2.
6. **Tanpa `DATABASE_URL`** → app tetap jalan: `/history` menampil StatePanel error ("Penyimpanan belum dikonfigurasi"), halaman lain tidak terpengaruh. Pin: verifikasi manual Task 4.

### Task 2: Helper murni `lib/history-state.ts` (TDD)

**Files:**
- Create: `lib/history-state.ts`, `tests/history-state.test.ts`

**Interfaces:**
- Produces (dipakai Task 3–6):
  - `type Range = { from: number; to: number }`
  - `type ChapterRead = { lastChapter: { slug: string; number: number } | null; readSet: Range[] }`
  - `type WatchPayload = { position?: number | null; duration?: number | null }`
  - `mergeRanges(set: Range[], n: number): Range[]` — gabung/tenggelamkan rentang yang berurutan/overlap (1 → [{1,1}] ; 3 masuk [{1,2}] → [{1,3}])
  - `inRanges(set: Range[], n: number): boolean` — exact per angka (float aman)
  - `mergeWatchPayload(prev: WatchPayload | null, next: WatchPayload): WatchPayload` — `position = max(prev?.position ?? next.position, next.position)`; `duration` selalu dari `next`; field lain from next
  - `resumeFor(payload: WatchPayload | null, episodeId: string, wantedEpisodeId: string): number | null` — `null` bila payload kosong / episode beda / `isCompleted(pos, dur)`; else `position` (detik)
  - `isCompleted(position: number|null, duration: number|null): boolean` — `false` bila pos/dur falsy/tak-angka; else `pos/dur ≥ 0.95`
  - `formatPosition(sec: number|null): string` — `null→"0:00"`, `754→"12:34"`, `4523→"1:15:23"`
  - `fmtRel(dateISO: string): string` — "baru saja" | "x menit lalu" | "x jam lalu" | "x hari lalu" | `Tanggal `d MMM yyyy``
  - `parseNum(v: string|number|null|undefined): number|null` — "Chapter 10.5"→10.5, "Ep 12"→12, 10→10, "TBD"→null (pola serupa numeral di ChapterList)

### Task 3: Server Actions `lib/history.ts` (upsert, trim, baca)

**Files:**
- Create: `lib/history.ts`, `tests/history-db.test.ts`
- Consumes: `db()` (Task 1), semua helper Task 2, `auth()` dari `@clerk/nextjs/server`

**Interfaces:**
- Produces (dipakai Task 4–6, semua async, masing-masing `void` bila dipanggil dari client):
  ```ts
  export type HistoryRow = { domain: "komik"|"anime"|"drakor"|"movie"; ref: string; title: string;
    posterUrl: string|null; payload: Record<string, unknown>; updatedAtISO: string };
  export type Domain = HistoryRow["domain"];
  const PAGE_SIZE = 50; const HISTORY_MAX = 500;  // konstanta spec
  recordComicRead({ mangaSlug, title, chapterSlug, chapterNumber, posterUrl? }): Promise<void>
  recordAnimeWatch({ source, animeSlug, title, episodeId, episodeNumber, posterUrl? }): Promise<void>
  recordDrakorProgress({ id, title, episodeId, episode, position, duration, posterUrl? }): Promise<void>
  recordMovieProgress({ slug, kind, episodeId, title, season?, episode?, position, duration, posterUrl? }): Promise<void>
  getHistoryRows(page: number): Promise<{ rows: HistoryRow[]; hasNext: boolean; hasPrev: boolean }>
  getComicReadState(mangaSlug: string): Promise<ChapterRead>       // dari Task 2
  getWatchResume(d: { domain: Domain; ref: string; episodeId: string }): Promise<{ resumeAt: number } | null>
  deleteHistoryRow(d: { domain: Domain; ref: string }): Promise<void>
  ```
- Semua function WAJIB mengambil `userId` dari `auth()` (NEVER percaya argumen client); `userId` null → return tanpa efek (skip, tanpa throw).
- Domain/`ref`: komik→`ref=mangaSlug`; anime→`ref=${source}:${animeSlug}`; drakor→`ref=id`; movie→`ref=slug`
- Payload shapes (exact, dari spec): komik `{ lastChapter: {slug, number}, readSet: Range[] }`; anime `{ source, animeSlug, episode: {episodeId, number|null} }`; drakor `{ episodeId, episode, position, duration }`; movie `{ kind, season?, episode?, episodeId, position, duration }`
- Komik merge: SELECT payload → `readSet=mergeRanges(old.readSet, chapterNumber)`; `lastChapter` = max (bila `number ≥ old.number`); then upsert `ON CONFLICT (user_id,domain,ref) DO UPDATE SET title, poster_url (bila param ada), payload=EXCLUDED.payload, updated_at=now()`.
- Watch merge: SELECT payload → `mergeWatchPayload(prev, next)` → upsert (idem).
- Trim: post-upsert, `SELECT domain, ref, updated_at FROM history WHERE user_id=$1 ORDER BY updated_at DESC` → order ulang di TS (watch domain `anime/drakor/movie` dahulu, komik belakang) → bila panjang > 500: DELETE baris indeks ≥ 500 (chunk IN (...)).
